# family-app

Monorepo for the Family app. Each domain lives in its own folder and has its own `CLAUDE.md` with domain-specific rules. Claude Code loads the domain file automatically when working on files inside that folder.

| Folder      | Domain        | Stack                                    | Instructions                             |
|-------------|---------------|------------------------------------------|------------------------------------------|
| `backend/`  | API server    | ASP.NET Core 10, PostgreSQL, EF Core     | [backend/CLAUDE.md](backend/CLAUDE.md)   |
| `frontend/` | Web client    | Vue 3, Composition API                   | [frontend/CLAUDE.md](frontend/CLAUDE.md) |
| `mobile/`   | Mobile client | Kotlin Multiplatform, iOS and Android    | [mobile/CLAUDE.md](mobile/CLAUDE.md)     |

## Status

The stack for each domain is chosen, but no domain has been scaffolded yet. Some secondary choices are still open and are marked "not decided" in the domain files. Record each decision in that domain's `CLAUDE.md` when it is made, and confirm the listed commands once the project is scaffolded.

## Architecture

- `backend/` holds the authoritative copy of all data and enforces the business rules.
- `mobile/` is local-first. It works offline against a local database and syncs with the backend when online. The sync protocol is not decided yet.
- All IDs are UUID version 7, generated by whichever side creates the record, so records can be created offline.
- Family members and user accounts are separate. Children, grandparents and pets can be members without an account. A user can be a member of several families, and memberships can end. Every piece of family data belongs to one family. Each API request acts for one family, chosen in the route, and the backend checks membership and filters by `family_id` on every request.
- Health data is medical data and is stored only in encrypted form. It is anything about a member's body, health or care, such as body measurements and sizes, body composition, the baby feeding journal, sleep records, medical examinations, vaccinations, medications and attached files. The backend encrypts it at the application level before it reaches PostgreSQL, the mobile app keeps it in an encrypted local database, and the web client never stores it in the browser. This is server-side encryption, not end-to-end: the backend can decrypt it for active members of the family. The backend also writes an audit log entry for every view, change, delete or export of health data. The design is in the "Health data encryption" section of [backend/CLAUDE.md](backend/CLAUDE.md), with client rules in each client's file.
- `frontend/` and `mobile/` are clients. They talk to the backend only through its HTTP API and never share a database or import backend code.
- The API contract is owned by `backend/`. Any change to it must be reflected in both clients in the same piece of work, or flagged clearly if not.

## Repo-wide rules

- Keep changes scoped to one domain when possible. Cross-domain changes should say so in the commit message.
- Never commit secrets. Use `.env` files locally and commit only `.env.example` with placeholder values.
- Each domain manages its own dependencies inside its own folder. Do not add a root-level package manifest unless the repo moves to a workspace setup on purpose.
- Delete a folder's `.gitkeep` once it has real files.

## Git
